### 1.3 NT 走查

- NT（B 物理 (n,k)，transb=T）：通用 level3 内核（hygon 无 bfgemm_nt tune 段，回落 NVIDIA 缺省池）。v4 官跑 median 0.934（v3 0.946、v2 期同进程 A/B 0.979），波动属 torch 基线跨进程漂移（见 §3/§4）。


### 1.4 TT 走查

## 3. 方法学说明（bf16 特有）

- DTK 25.04 hipBLAS 对 bf16 无可用的 gemmEx 类入口，`benchmark/gemm_perf_common.py::cublas_bfgemm` 在 `IS_HYGON` 下改走 torch bf16 matmul（rocBLAS Tensile bf16，fp32 累加，与 FlagBLAS 内核语义一致）；`cublas_bfgemm_reference` 以 fp32 on-device matmul 作精度 oracle 后回投 bf16。

- TN 布局基线说明：TN 调用下基线同样按 CUBLAS 布局把 A 视为 (m,k)（物理 (k,m) 转置视图）交给 torch，与 FlagBLAS TN 的物理布局对齐。

- **torch 基线跨进程漂移（真实存在）**：torch bf16 matmul 基线在同一日不同进程间对个别 shape 亦波动 5–17%（如 NT 4096×24576×8192 官跑进程 9.59ms、同进程交错 A/B 10.43ms）；9/3 与 9/4 之间整体亦漂移（如 NN 2048³ torch 0.129→0.111ms）。因此逐 shape speedup 以**同进程交错测量**（§3.2）为准最稳，多轮官跑 median 用于复现性确认。

- **测量口径勘误（重要，已澄清此前 "快/慢窗口" 疑云）**：本机存在 flag_blas 可编辑安装（pip editable `.pth` → `/data/zhc/flag-blas`，2026-08-17 快照，不含本次 bfgemm 任何改动）。凡未以 `PYTHONPATH=<工作树>/src` 显式指向本工作树的独立脚本，`import flag_blas` 均命中该过期副本：NN 大 shape 回落旧配置池（128×128×64，延迟与 9/3 旧值逐位一致，如 8192³ 10.51ms）。此前疑似 "NN/TT 官跑快值不可复现" 实为**探针误用过期副本**，非真实状态窗口：官方 pytest（仓库根目录运行、src 入 path）与显式指向工作树的探针测得同一 fast 配置（NN 8192³ 7.53ms、8191³ 11.52ms），15:05 与 15:53 两轮官跑逐位稳定。**结论：所有官跑数字有效；此前手动脚本/旧 A/B 的 "慢值" 全部作废。**

- 正确性：37×4 全部 PASS（pytest 断言含 beta=0/β≠0，rel err ≈ 1e-3 bf16 ULP 级）。

- 复测口径：**v4 = pool-27（27 configs，相对 v3 无改动）下每变体一轮完整官跑（2026-09-04 14:06–14:16），作为 §1/§2 当前口径**；v3 为 pool-27 首轮全量官跑（17:35–18:02）。v3↔v4 表内逐 shape 差异即 run-to-run 噪声（大 shape flag 延迟逐位复现，见 §1 脚注）。v2 池时期 NN/NT/TT（15:05–15:18）与 typ（15:53–16:02）两轮 median 稳定，TN 另有 14:31 一轮（0.960/0.960/0.980）。§3.2 保留 v2 期交错 A/B 记录供对照。

- NN：24/37 shape flag 延迟下降 ≥3%（其中 ≥8% 的 18 个见下表），仅 512³ 一个 shape 上升 +6.5%（autotune 在新增 config 中选点抖动，单 shape 噪声）；

## 4. 结论

- **TN（本任务目标变体）：median 1.000 ≥ 0.95，sp≥0.95 23/37（v4 pool-27 官跑），全部正确**；v3 1.009/22、v2 池 0.960，连续五轮官跑（0.960/0.960/0.980/1.009/1.000）无回退。

- **NN：median 0.922 → 0.974 → 0.991**（sp≥0.95 18→20→21/37）。pool-27 新增 8 个 config（19→27）为 NN 及池共享内核（TT/TN 大 shape 复合）在瘦/中/非方形 shape 上补齐缺失 tile 组合，v2→v3 24/37 shape flag 延迟下降 3–38%；仅 512³ 单 shape +6.5% 抖动（v3 单轮），v4 复查整体无回退（8192³ 5.5432ms 逐位复现）。

- TT：median 1.271 → 1.381 → **1.370**（sp≥0.95 33→34→34/37），同池受益，v4 复查与 v3 一致。NT 不改池（回落 NVIDIA 缺省池），v3/v4 官跑 0.946/0.934 波动为 torch 基线漂移，v2 期同进程 A/B 口径 0.979 更准。

- 剩余短板是结构性上限而非 config 问题：非对齐/超大方形 shape（8191³、8192³、4096×24576×8192、8192×28672×8192 等，NN/TN sp 0.38–0.60）flag 实测 ≈193–203TF/s（v4 官跑：8192³ 5.5432ms≈198TF、4096×24576×8192 8.4208ms≈196TF、4096×8192×28672 9.9874ms≈193TF、8192×28672×8192 18.9512ms≈203TF，与 v3 逐位一致；最优均 (256,256,BK64,w8,s2)）。raw 扫描 20+ config（w4/8/16 × BK32/64 × 128/256 tile、GROUP_M 4/8/16）确认无 >199TF 候选。反汇编定性：Triton bf16 `tl.dot` 发射**原生 bf16 mmac**（`v_mmac_f32_16x16x16_bf16`，与 fp16 变体 `…_f16` 同宽同速、实测同速），并非走 fp16 转换路径；相对 rocBLAS 原生 bf16 Tensile（更宽 mfma，wrapper 口径 ≈333TF/s / 直调 ≈384TF/s）的 ~0.5–0.6 缺口属 Triton 后端指令宽度/发射层（16×16×16 vs 宽 mfma），tile 级调参已到顶点。
